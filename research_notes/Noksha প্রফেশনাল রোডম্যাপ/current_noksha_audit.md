Research date: 2026-11-19. Scope: local plugin tree only (`noksha.php`, `src/`, `admin-src/`, `assets/`, `templates/`, `build/` references, `package.json`). No plugin files were modified. Credentials were not dumped.

## What screens, REST APIs, section types, payments, analytics, brand/settings, and front-end rendering already exist?

### Takeaway
Noksha v0.1.1 is already a Bangladesh-oriented landing-page + checkout product: one React admin SPA (home, pages/editor, orders, analytics, payments, brand, settings), a `noksha/v1` REST surface, nine section types including custom HTML and order form, COD + manual bKash/Nagad + SSLCommerz gateways, first-party funnel analytics, brand tokens, pixel ID settings, and a theme-stripped public offer renderer at `/offer/{slug}/`.

## How is the page editor structured after the recent redesign (content list + preview + inspector panels, custom HTML block, focus mode)?

### Takeaway
The redesigned editor is a three-zone focus workspace: left **content list / stacked inspector panels**, center **device-framed live preview iframe**, top chrome for title/status/save; entering a page hides the global app rail (“focus mode”); custom HTML is a first-class section with a 20k char code textarea and capability-aware sanitization.

### Cited Findings
- Editor route `pages/{id}` sets `nk-app is-editing`, which collapses grid to one column and **hides `.nk-rail` and `.nk-menu`**. — [admin-src/App.js](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/admin-src/App.js); [admin-src/style.css](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/admin-src/style.css) (`.nk-app.is-editing`)
- Layout: `.nk-ed-top` (back, title, dirty state, phone/desktop toggle, view live, save/publish) + `.nk-ed-body` = `.nk-ed-side` + `.nk-ed-stage` preview. — [admin-src/screens/Editor.js](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/admin-src/screens/Editor.js)
- View state machine on the side panel: `home` ContentList → `add` type picker → `section` SectionFields → settings panels `offer` / `checkout` / `page` / `colors`. — Editor.js `view.kind`
- ContentList: drag-and-drop reorder, up/down, hide/show, summary text, “Add block”, then nav rows for Offer / Checkout / Page / Colors. — Editor.js `ContentList`
- Preview: POST `/preview` debounced **350ms**, `srcDoc` iframe, injects click-to-select CSS (`data-nk-section`), blocks form submit, restores scroll; phone vs desk device chrome. — Editor.js preview `useEffect` / `onFrameLoad`; Renderer adds `data-nk-section` only when `$preview` true — [Renderer.php](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/src/Pages/Renderer.php)
- Custom HTML section: textarea `maxLength` 20000, help text switches on `nokshaBoot.unfilteredHtml`; server `Sanitizer::html` uses raw HTML if `unfiltered_html` or already stored, else `wp_kses_post`. Rendered unescaped inside `<section class="nk-section nk-html">`. — Editor.js; [Sanitizer.php](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/src/Pages/Sanitizer.php); [Renderer.php](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/src/Pages/Renderer.php)

### Inferences
- Pattern is **form-first inspector + server-rendered preview**, not canvas/inline WYSIWYG editing of text on the page.
- “Focus mode” in product language maps to `is-editing` (rail hidden), not a separate UI toggle.
- Container queries address mid-width editor UX; residual risk remains when WP admin chrome + tall toolbars leave little vertical space.

### Gaps
- No undo/redo, autosave, revision history, or multi-select observed in Editor.js.
- No visual regression evidence re-run at 1024px in this research pass (only CSS + prior transcript).

## What technical debt or quality risks show up (security of HTML blocks, build pipeline, i18n, tests, performance of preview, admin UX at 1024px, SSLCommerz deferred)?

### Takeaway
Main risks: privileged custom HTML XSS surface, SPA/i18n dual systems, no first-party automated tests found, preview round-trips on every edit, mid-width admin UX still constrained by WP chrome, and SSLCommerz code exists but product/ops validation was deferred (default off; availability checks omit `ssl_ready`).

- **Build pipeline**: `@wordpress/scripts` via `npm run build` / `start`; webpack entry only `admin: ./admin-src/index.js`; missing build files surface admin notice. `package.json` version **0.1.0** while plugin header **0.1.1**. Landing CSS/JS are static under `assets/` (not webpack). — [package.json](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/package.json); [webpack.config.js](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/webpack.config.js); [Menu.php](file:///C:/Users/USER/Local%20Sites/test/app/public/wp-content/plugins/noksha/src/Admin/Menu.php)
